## Full Review Findings

Ranked by impact. Phase 3 is read-only; no code was changed for these.

1. **HIGH — `scripts/train.py` is a 7,191-line monolith (140 defs).** It mixes the CLI (`main`), artifact indexing/redaction, checkpoint trust, long-run manifest/launcher generation, league health, and strategy reporting. `build_long_run_manifest` alone takes 39 parameters (`:5464`). This is the dominant maintainability and reviewability risk; the recent test split (`f08e300`) already establishes the seam-aligned pattern. Recommend splitting along the same seams (`artifact_index.py`, `checkpoint_trust.py`, `long_run.py`, `league.py`, `strategy.py`).
2. **MEDIUM — duplicated smoke helpers with divergent semantics.** `run_command`/`latest_artifact` are copied in `scripts/train_eval_smoke.py:35,65`, `scripts/smoke_suite.py:33`, `scripts/long_run_artifact_smoke.py:28,55`, `scripts/reward_shaping_smoke.py:22,48`. They already differ (some `check=True`, one wraps `CalledProcessError`). Recommend one shared helper module so timeout/error behavior cannot drift.
3. **MEDIUM — assert-as-guard in library code.** `src/arena_fighters/self_play.py:63` (see Security Findings LOW). Under `python -O` the guard disappears; use an explicit `raise`.
4. **MEDIUM — broad `except Exception` while scanning artifacts** (`scripts/train.py:1046,1715,3232,3260`). The fail-soft intent (record a `skipped` entry, keep scanning) is right, but catching everything can mask genuine programming errors as "skipped". Recommend narrowing to the expected parse/IO exceptions (`OSError`, `ValueError`, `TypeError`, `KeyError`) or logging unexpected types distinctly.
5. **LOW — `functools.lru_cache` on instance methods** (`src/arena_fighters/env.py:93,109`). Keyed on `self`, unbounded lifetime, and retains the instance; fine for the current few-env usage but a leak risk in long sweeps. A per-instance cache (or plain construction, since these spaces are cheap) is safer.
6. **LOW — redaction test coverage gap.** `tests/test_artifacts.py` exercises the assignment form of `PRIVATE_KEY=...` and the URL/header/JSON forms, but not the bare `-----BEGIN ... PRIVATE KEY-----` branch (`_PRIVATE_KEY_LINE_RE`) nor non-`command_log` artifact types. The branch works (verified manually above); add a fixture line for it.
7. **LOW — no CI and no lint/type configuration.** `.github/` is absent and `pyproject.toml` defines no `[tool.ruff]`/`[tool.pytest.ini_options]`; tests run only locally and the ruff findings above drift over time. Adding a minimal `ruff`/`pytest` config (and a CI job) would lock in the current clean state.
8. **LOW — `tests/test_longrun.py` is a new 2,440-line catch-all** (59 tests). The last commit split the old callback catch-all; this file recreates the same shape one level down. Consider splitting by behavior seam.
9. **INFO — `B023` loop-closure warnings in `src/arena_fighters/evaluation.py:780-825` are false positives.** The nested `numeric_metric`/`count_metric`/`behavior_count_metric` closures capture the loop's `summary`/`matchup_context`, but they are invoked within the same iteration and never stored, so no late-binding bug exists.
10. **INFO — dependency hygiene is sound.** `uv.lock` is committed, `requires-python >= 3.12`, and the five runtime deps are lower-bounded and resolved via the lock; `tensorboard`/`pytest` stay in the `dev` extra. Residual: no vulnerability scan was run (see Remaining Risks).

## Remaining Risks

- No end-to-end training/eval run was executed: `scripts/train.py` training paths, the CUDA/torch path, and the four `scripts/*_smoke.py` wrappers (which shell out to real training) were not run. Verification is the unit/smoke test suite plus static analysis only.
- No dependency vulnerability scan (`pip-audit`/`uv` audit) was performed, and the custom PyTorch CUDA index (`[tool.uv.index] pytorch-cu124`) makes a network-dependent audit non-reproducible here. Unknown CVEs in `torch`/`stable-baselines3` remain unassessed.
- Redaction coverage for artifact types other than `command_log` was assessed by reading code, not by executing a fixture for every type (documented as Security Findings LOW #1).
- `ruff`/`vulture` were run ad-hoc via `uvx` and are not project dependencies; a future ruff release may surface different findings.
- No type checker (`mypy`/`pyright`) is configured, so annotation-level defects were not systematically checked.
- Generated shell launchers (`_shell_arg`/`_with_output_redirect`) were reasoned about, not executed end-to-end; the quoting risk is documented above.
